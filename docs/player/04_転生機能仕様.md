# 転生機能仕様

* プレイヤーは一定条件を満たすと、自身を転生させて再育成を開始できる。
* 本機能は既存プレイヤーの更新で表現し、新規プレイヤー作成や別テーブルへの履歴退避は行わない。
* 転生回数は `internal.players.rebirth_count` で保持する。

## 目的

* レベル 100 到達後の継続的な育成導線を提供する。
* プレイヤーレベルの上限は 100 であり、転生必要レベルと一致する。したがってレベル 100 到達後にプレイヤーレベルを伸ばす手段は転生のみとなる。
* これまで育てたジョブ熟練と習得済みスキルを活かしつつ、再び低レベル帯から育成できるようにする。

## 転生条件

* 認証済みユーザーのみ実行できる。
* 認証ユーザーから `PlayerId` を取得できない場合は `401 Unauthorized` とする。
* プレイヤーが存在しない場合は `404 NotFound` とする。
* プレイヤーレベルが 100 未満の場合は転生できない。
* 所持 Gold が 100000 未満の場合は転生できない。
* 条件未達時は `409 Conflict` とし、ドメインルール違反として扱う。

## 転生時の更新内容

* 転生時に 100000 Gold を消費する。
* 転生回数 `rebirth_count` を 1 増やす。
* プレイヤーレベルは 1 にリセットする。
* プレイヤー経験値 `exp` は 0 にリセットする。
* 現在ジョブは維持する。
* 現在ジョブの職業レベル `jobLevel` は 1 にリセットする。
* マスター済みジョブ `MasteredJobs` はそのまま引き継ぐ。
* 習得済みスキル `MoveSet` はそのまま引き継ぐ。
* 画像、名前、クエストクールダウンは変更しない。

## ステータス継承

* 継承対象は `MaxHp`、`MaxMp`、`Strength`、`Defense`、`Intelligence`、`Luck`、`Speed` の 7 項目とする。
* 各項目ごとに独立して 25% から 35% までの整数継承率を抽選する。
* 継承率は `25, 26, ..., 35` の一様乱数とする。
* 転生後ステータスは `floor(転生前ステータス * 継承率 / 100)` で求める。
* `MaxHp` は `Status` の制約上 1 未満にできないため、計算結果が 0 の場合でも 1 を下限とする。
* `MaxMp`、`Strength`、`Defense`、`Intelligence`、`Luck`、`Speed` は 0 を下限とする。
* 装備補正は継承計算に含めず、プレイヤーの素の `Status` を基準とする。

## 転生ボーナス

* 転生回数に応じて、プレイヤーレベルアップ時の各成長値に恒久ボーナスを付与する。
* ボーナス量は各成長値ごとに `転生回数 * 1%` とする。
* 成長値は整数のため、各レベルアップごとに単純な切り捨ては行わない。
* 代わりに、その転生周回でレベル 1 から現在レベルまでに得るはずの累積ボーナス `floor(成長値 * (現在レベル - 1) * 転生回数 / 100)` を基準とし、前回レベルとの差分だけを今回のレベルアップで加算する。
* これにより、成長値 `3` かつ転生 1 回のような小さい値でも、複数回のレベルアップを通じて端数が蓄積され、一定間隔で追加成長として反映される。
* このボーナスはプレイヤーレベルアップ時の基礎成長にのみ適用し、職業レベルアップ自体の仕様は変更しない。

## 必要経験値

* プレイヤーレベルの必要経験値は `level * 10` とする。
* プレイヤーレベルの上限は 100 であり、レベル 100 では次レベルが存在しないため必要経験値は `0` を返す。
* レベル上限の導入により到達不能となったため、レベル 2000 超の超線形カーブは廃止した。
* 職業経験値は廃止した。職業レベルはプレイヤーレベルアップ時に同時に 1 上がる。
* したがってプレイヤーレベルが 100 に到達した後は、経験値も職業レベルも増加しない。
* ジョブの `master_level` は最大 100 とし、プレイヤーレベルの上限と一致させる。

## 永続化

* 転生による更新対象は既存 `internal.players`、`internal.player_moves`、`internal.player_master_jobs` のうち、実際に値が変わるプレイヤー本体のみとする。
* `player_moves` と `player_master_jobs` は内容を維持するため、転生専用の追加テーブルや追加カラムは作成しない。
* `internal.players` に `rebirth_count` を追加するため、EF Core マイグレーションを作成する。

## API

### 転生実行

* `POST /player/rebirth`
* 認証必須とする。
* リクエストボディは不要とする。
* 正常時は `200 OK` を返す。
* レスポンスには少なくとも以下を含める。
  * `message`
  * `userId`
  * `userName`
  * `rebirthCount`
  * `job`
  * `level`
  * `jobLevel`
  * `exp`
  * `gold`
  * `status.baseValues`
* 習得済みスキルやマスター済みジョブは既存の `GET /player` で再取得できることを前提とする。

## エラーメッセージ方針

* レベル条件未達時は「転生にはレベル100以上が必要です。」を返す。
* Gold 不足時は「転生には100000 Goldが必要です。」を返す。
* プレイヤー未存在時は既存 API と同様に「プレイヤーが見つかりません。」を返す。

## クライアント表示方針

* クライアントは転生前に必要条件とリセット内容を明示する。
* クライアントは転生後に更新済みレベル・Gold・基礎ステータスを表示できるようにする。
* 継承率そのものは初期実装ではレスポンスに含めず、結果ステータスのみ表示する。

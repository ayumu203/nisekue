# 宝の地図機能仕様

## 目的
- 宝の地図はプレイヤーが「旅」に出かけ、時間経過で報酬を得ることができる消費アイテムとして位置づける.
- 既存のクエスト/冒険コンテンツと並列するサブ体験として, クエストのステータスパネルに近い演出で旅の進行状況を提示する.
- アイテム一覧からの直接使用はできず, 専用の「宝の地図」メニューからのみ発動できることで, 専用UIと挙動を定義する.

## アイテムとしての扱いと入手経路
- 宝の地図そのものはアイテムテーブルに登録し, 在庫管理が行えるが, 実際の使用操作は専用メニュー上でのみ許可する.
  - アイテム一覧からは使用できないようにフィルターする(表示はするが仕様ボタンは出さない).
  - メニューにはレア度(グレード)や残数, 所要時間を並べて表示し, プレイヤーが改めて選択する流れとする.
- 宝の地図はクエスト報酬/マーケットなど様々な手段で取得できる想定だが, いったん獲得後は専用UIで消費される.

## 使用フロー
1. メインメニューに「宝の地図」項目を設け, 選択すると所持している地図一覧を表示する.
2. 各地図ごとに以下の情報を表示: グレード(S~D), 所要時間, 報酬の方向性(アイテム/装備/経験値/ゴールド), 旅で表示する演出文.
3. プレイヤーが地図を選択 → 「旅に出る」を決定すると, 地図を1枚消費して旅がスタートする.
4. 旅はサーバーで開始時刻/終了時刻を記録し, 終了までのタイマー状態を管理する.
5. 旅の進行中は専用のステータスパネル(クエストステータスに近いグラフィック)を表示し, プレイヤー/他キャラが冒険しているイラストや「あと○分」の表示を出す.
6. プレイヤーがログアウトしても旅は継続し, 次回ログイン時には進行状態または完了待ちとして表示.
7. 旅の途中や完了直後にキャンセル/中断は不可とし, 所要時間が経過したら自動的に報酬確定状態へ移行する.
8. 終了後プレイヤーのルームへシステムから通知が送られる.

## 旅の進行と報酬
- 旅ごとの所要時間・報酬構成は地図固有で, グレード別のベース仕様を定義する.
  - グレード: S, A, B, C, D (Sが最長時間/高報酬, Dが短時間/少報酬).
  - それぞれの地図に固定の所要時間と報酬レンジ(アイテム/装備/経験値/ゴールド)を紐づける.
- 報酬は旅完了後にまとめて付与され, クエスト報酬のように「取得済み」表示とダイアログを出す.
- 報酬アイテム/装備は地図固有のプールからランダムに決定し, 事前に報酬候補を定義しておく.
- 経験値は旅に参加可能なキャラクターに対して同一量を付与し, パーティ全体や操作キャラだけにするかは実装で定義する.
- ゴールドも同様に, 報酬テーブル内で固定値またはレンジ指定.
- 旅の報酬は「クエスト完了と同様に」通知されるが, 同時に複数旅が走ると重複する可能性があるため, 受け取り履歴を保存する.

## UI/UX要件
- 宝の地図一覧画面では, 地図名・グレード(S~D)・所要時間・所持数・報酬傾向を表示し, 「旅に出る」操作を明示する.
  - 各地図の詳細からは旅の演出文と報酬候補(アイテム/装備/経験値/ゴールド)を参照できるようにする.
- 旅の進行画面はクエストステータスパネルに似た構成で, 背景にプレイヤーと他キャラが冒険しているイラストを配置する.
  - 右上に残り時間のカウントダウンと進行バー, ステータス欄に「旅の概要」「獲得予定報酬」を記載する.
  - 進行中の地図詳細はロックされ, 進行状況の可視化に特化した画面とする.
- 旅完了後は画面に「報酬を受け取る」ボタンを表示し, 受け取り後に完了済みデータを一覧から除外するか履歴に移す.

## サーバー/データ構造
- `TreasureMap` エンティティ (id, name, grade, duration, rewardPoolId, marketFlag, ownedQuantityなど).
- `TreasureMapExpedition` レコード (playerId, mapId, startedAt, endsAt, rewardResult, status[進行中/完了/受け取り済み]).
- 所要時間は秒単位で `duration` に保持し, 終了判定は `endsAt` を基に行う.
- 報酬は `rewardPoolId` を参照してアイテム/装備/経験値/ゴールドを組み立て, 旅完了時に `TreasureMapExpedition` に結果を記録する.
- マーケット出品時は `TreasureMap` の `marketFlag` を立て, グレード, 所要時間, 期待報酬を出品情報として表示する.
- 所持地図の数量管理は既存のアイテム在庫テーブルを再利用するが, アイテム一覧側の露出フラグが立っていないことを保証.
- 進行中の旅はプレイヤー単位で最大幾つまで許可するかも含め, 仕様として定義する.

## マーケット連携
- 地図はマーケットに出品/購入できる商品とする.
- 出品情報にグレード/所要時間/報酬の傾向を含めることで, プレイヤーは交換前に価値を判断できる.
- 取引後も専用メニューから使用する点は変わらず, 所持地図の更新は即時反映される.
- マーケットで地図を獲得すると, 通常の宝の地図と同じ扱いで専用メニューから使用できる.

## コードオーナー確認が必要な仕様
- 同時に複数の地図を旅に出せる上限数と, 上限に達した場合の UI/制御はどうするか?
  - 回答: 上限は1枚。上限に達している間は「旅に出る」ボタンを表示せず、リクエストが来てもエラーを返す。
- 旅の進行をプレイヤーがログアウトしている間も継続させるか, サーバー次第で一時停止 (キャンセル) させるか?
  - 回答: ログアウト中も旅は継続させる。
- 報酬の具体的な算出ロジック(ランダム/確定/成功率) や, 失敗/帰還イベントを想定するか?
  - 回答: ランダムで選択し、レベルにより成功率を変動。失敗時は少量報酬を付与。
- 経験値/ゴールド配分はクエストと同等なのか, 例: 旅参加キャラ分 vs オーナーのみで決めるべきか?
  - 回答: CSVマスタに定義、オーナーだけに付与。通常クエストの5〜10倍程度の大きめ報酬。
- グレードごとの所要時間や報酬レンジの初期値/マスターデータの粒度をどう定義するか?
  - 回答: CSVで詳細を定義する。
- マーケット出品情報に含める要素(報酬説明, 地図の説明文, グレード) と, 出品手数料/取引制限 は必要か?
  - 回答: 報酬説明・地図説明・グレードを含めるが、手数料・制限は不要。
- UI演出(絵柄・進行中表示)は既存のクエスト画面の流用で十分か, 新規にアセットが必要か?
  - 回答: 流用で問題ないが、ボタン等の配置はせず進捗バーなどを表示する。
- 地図の消費タイミングと報酬の確定タイミングを切り離す必要があるか (例: 先に消費, 後で受取) ?
  - 回答: 消費は先、報酬は後受取。
- 特定の地図に対してレベル・ジョブ・進行状況の条件をつける必要性があるか?
  - 回答: 条件なし。

# デバッグ機能

プレイヤーのレベル・ステータス・スキル・アイテムなどを直接書き換え、動作確認やバランス調整の確認を楽にする機能。

## 使える条件

`DebugAccessService.CanUseAsync` で判定する。

| 条件 | 結果 |
| --- | --- |
| 設定 `Debug:Enabled` が false | 誰も使えない（デバッグ用の操作 API 自体を登録しない） |
| 設定 `Debug:AlwaysEnabled` が true | 誰でも使える |
| それ以外 | `internal.players.role` が `admin` のプレイヤーだけ使える |

環境ごとの設定:

| 環境 | `Debug:Enabled` | `Debug:AlwaysEnabled` | 設定の場所 |
| --- | --- | --- | --- |
| ローカル（`dotnet run`、Codespaces） | true | true | `server/Properties/launchSettings.json` |
| ステージング（Azure、`Development`） | true | false | `appsettings.json` の既定値 |
| 本番（Oracle VM、`Production`） | false | false | `appsettings.Production.json` |

- 本番には admin のプレイヤーを作らない運用。`Debug:Enabled=false` は誤って admin にしてしまった場合の保険
- `IsDevelopment()` はステージングでも true になるので、デバッグ機能の判定には使わない

## role の設定

ゲームの API からは変更できない。Supabase の SQL エディタで設定する。

```sql
-- 付ける
UPDATE internal.players SET role = 'admin' WHERE id = '<auth.users.id>';
-- 外す
UPDATE internal.players SET role = NULL WHERE id = '<auth.users.id>';
```

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/debug/status` | `{ canUseDebug: boolean }`。`Debug:Enabled` が false でも登録され、false を返す |
| * | `/debug/*` | デバッグ用の操作。認証と `CanUseAsync` の判定をグループ共通のフィルターで行い、使えなければ 403 |

## 画面

- ホームの「その他」の下に「デバッグ」ボタン（`/debug/status` が true のときだけ表示）
- `/debug` ページに機能ごとのセクションを並べる

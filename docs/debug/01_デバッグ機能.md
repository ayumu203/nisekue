# デバッグ機能

プレイヤーのレベル・ステータス・スキル・アイテムなどを直接書き換え、動作確認やバランス調整の確認を楽にする機能。

## 使える条件

`DebugAccessService.CanUseAsync` で判定する。

| 条件 | 結果 |
| --- | --- |
| 設定 `Debug:Enabled` が false | 誰も使えない（デバッグ用の操作 API 自体を登録しない） |
| 設定 `Debug:AlwaysEnabled` が true | 誰でも使える |
| それ以外 | `internal.players.role` が `admin` のプレイヤーだけ使える |

環境ごとの設定:

| 環境 | `Debug:Enabled` | `Debug:AlwaysEnabled` | 設定の場所 |
| --- | --- | --- | --- |
| ローカル（`dotnet run`、Codespaces） | true | true | `server/Properties/launchSettings.json` |
| ステージング（Azure、`Development`） | true | false | `appsettings.json` の既定値 |
| 本番（Oracle VM、`Production`） | false | false | `appsettings.Production.json` |

- 本番には admin のプレイヤーを作らない運用。`Debug:Enabled=false` は誤って admin にしてしまった場合の保険
- `IsDevelopment()` はステージングでも true になるので、デバッグ機能の判定には使わない

## role の設定

ゲームの API からは変更できない。Supabase の SQL エディタで設定する。

```sql
-- 付ける
UPDATE internal.players SET role = 'admin' WHERE id = '<auth.users.id>';
-- 外す
UPDATE internal.players SET role = NULL WHERE id = '<auth.users.id>';
```

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/debug/status` | `{ canUseDebug: boolean }`。`Debug:Enabled` が false でも登録され、false を返す |
| * | `/debug/*` | デバッグ用の操作。認証と `CanUseAsync` の判定をグループ共通のフィルターで行い、使えなければ 403 |
| GET | `/debug/moves` | 全スキルの `{ moveId, name }` 一覧 |
| PUT | `/debug/player/status` | 基本ステータス 7 項目を指定値にする（命中・回避などは保持） |
| POST | `/debug/player/moves` | `{ moveId, slotIndex? }`。slotIndex 省略時は通常の習得と同じ（空きスロット、無ければ最古を外す）。指定時はそのスロットに置き、習得済みなら元のスロットから移す |
| DELETE | `/debug/player/moves/{slotIndex}` | スロットを空にする |
| GET | `/debug/templates` | テンプレートの `{ templateId, name }` 一覧（`02_テンプレート.md`） |
| POST | `/debug/player/template` | `{ templateId }`。テンプレートを取り込む（進行状況を作成直後に戻してから手順を実行）。`{ level, job, masteredJobs }` を返す |
| POST | `/debug/player/level` | `{ level }`。指定レベルまで 1 レベルずつ必要経験値を足して通常の `LevelUp` を実行する（成長・スキル習得・ジョブのマスターも通常どおり）。下げることはできない。`{ level, newlyLearnedMoveIds, hasMasteredCurrentJob }` を返す |
| POST | `/debug/player/master-jobs` | `{ jobs: Job[], unlockRoadmap }`。指定ジョブをマスター済みにする（`Player.MarkJobAsMastered`）。現在のジョブを含むと、そのジョブのスキルをすべて習得させる。職業レベルは変えない。unlockRoadmap なら各ジョブのロードマップも解放 |
| POST | `/debug/player/job` | `{ job }`。転職の条件（前提ジョブのマスター・レベル）を無視して転職する（`Player.ChangeJob(ignoreRequirements: true)`）。職業レベルは 1 になる。見習いと現在のジョブは不可 |
| GET | `/debug/items` | 全アイテムの `{ itemId, name, maxStack }` 一覧 |
| GET | `/debug/equipments` | 全装備の `{ equipmentId, name, equipmentType }` 一覧 |
| POST | `/debug/player/items` | `{ itemId, quantity }`。所持数はスタック上限で止まる。所持枠の上限は確認しない。入手後の所持数を返す |
| POST | `/debug/player/equipments` | `{ equipmentId, count(1〜20), plusValue?(0〜100) }`。所持品に入る（耐久は最大、熟練度 0）。所持枠の上限は確認しない |

| POST | `/debug/player/gold` | `{ amount }`（1 以上）。ゴールドを加算する（`Player.GainGold`、int の上限で頭打ち）。加算後の所持ゴールドを返す |
| POST | `/debug/player/rebirth` | 転生の条件（Lv100 以上・100,000 G）を無視して転生する（`Player.Rebirth(ignoreRequirements: true)`）。ゴールドは減らさない。ステータスの継承と転生履歴の記録は通常の転生と同じ。`{ rebirthCount, level }` を返す |
| POST | `/debug/player/cooldowns/reset` | クエストの再参加待ち（`quest_cooldown_until`）とペットバトルの再戦待ち（`pet_battle_cooldown_until`）を解除する。訓練の再戦待ち（3 秒）は対象外 |
| POST | `/debug/treasure-map/complete` | 探索中の宝の地図の `ends_at` を現在時刻まで進める。受け取り処理と競合しても状態を上書きしないよう、探索中の行の `ends_at` だけを条件付きで更新する（`ITreasureMapExpeditionRepository.TryShortenEndsAtAsync`）。報酬の抽選は通常の取得・受け取り処理で行われる。探索中のものが無ければ 400 |

プレイヤー本体の操作（ゴールドを含む）は `DebugPlayerService` が `IPlayerMutationService`（行ロック付きの更新）経由で、アイテム・装備は `DebugInventoryService` が各リポジトリ経由で、待ち時間の解除は `DebugWaitService` が行う。転生は通常の `PlayerRebirthService` を `ignoreRequirements: true` で呼ぶ。

## 画面

- ホームの「その他」の下に「デバッグ」ボタン（`/debug/status` が true のときだけ表示）
- `/debug` ページに機能ごとのセクションを並べる

## サーバーを使わない機能

| 機能 | 内容 |
| --- | --- |
| チュートリアル | 今のアカウントのチュートリアルを「完了扱いにする」／「最初からやり直す」（転生のチュートリアルも含む）。進み具合はブラウザの localStorage（`nisekue:tutorial:<ユーザーID>:*`）にあるので、操作したブラウザでのみ有効。チュートリアルの吹き出しにも、デバッグ機能を使えるときだけ「スキップ（デバッグ）」ボタンが出る（押すと完了扱いにして再読み込み） |

# テンプレートユーザーデータのインポート（設計案）

> 状態：**設計案**。下の「決めてほしいこと」が決まってから実装する。

## やりたいこと

「Lv100 の戦士・装備一式あり」「転生 3 回の中盤」のような、決まった進行状況のデータを、自分のアカウントに一度で入れられるようにする。デバッグ機能（`01_デバッグ機能.md`）の 1 つとして、同じ利用条件（ローカルは常に可、それ以外は admin のみ。本番は `Debug:Enabled=false`）で動かす。

## 対象にするデータ

| データ | テーブル | 扱い（案） |
| --- | --- | --- |
| レベル・経験値・ジョブ・職業レベル・ゴールド・基本ステータス 7 項目・転生回数 | `players` | 入れる |
| 経験値倍率・マップ解放・ロードマップ解放のフラグ、エンドレス最高到達フロア | `players` | 入れる |
| スキル（10 スロット） | `player_moves` | 入れる |
| マスター済みジョブ | `player_master_jobs` | 入れる |
| 装備（装備中かどうか・耐久・熟練度・強化値） | `player_equipments` | 入れる |
| アイテム | `player_item_stacks` | 入れる |
| ペット（ボーナス値・待機中） | `player_pets` | 入れる（要確認） |
| 転生時のステータス履歴 | `player_rebirth_status_histories` | 入れる（要確認） |
| ペットバトルの戦績 | `player_pet_battle_stats` | 入れない |
| 名前・画像・role・クールダウン・最終アクティブ | `players` | 入れない（アカウント固有） |
| チャット・スレッド・クエスト・マーケット・ランキング・宝の地図 | 各テーブル | 入れない |

## テンプレートの形式（案）

ID は自動採番のものを持たず、マスタの ID（スキル・アイテム・装備・敵）だけを持つ JSON にする。

```json
{
  "id": "warrior-lv100",
  "name": "Lv100 戦士・装備一式",
  "description": "戦士でLv100。初期装備を+10で装備",
  "player": {
    "job": "Warrior",
    "level": 100,
    "exp": 0,
    "jobLevel": 100,
    "gold": 100000,
    "rebirthCount": 0,
    "status": { "maxHp": 900, "maxMp": 120, "strength": 300, "defense": 250, "intelligence": 80, "luck": 60, "speed": 150 },
    "expMultiplierFlags": 0,
    "mapUnlockFlags": 0,
    "roadmapUnlockFlags": 3,
    "endlessBestFloor": 0
  },
  "moveSlots": [101, 102, null, null, null, null, null, null, null, null],
  "masteredJobs": ["Apprentice", "Warrior"],
  "equipments": [
    { "equipmentId": 1001, "equipped": true, "plusValue": 10, "mastery": 0, "durability": null }
  ],
  "items": [{ "itemId": 3001, "quantity": 10 }],
  "pets": [{ "enemyDefinitionId": 1, "isStandby": true, "bonus": { "maxHp": 0, "maxMp": 0, "strength": 0, "defense": 0, "intelligence": 0, "luck": 0, "speed": 0 } }],
  "rebirthHistories": []
}
```

- `durability: null` は装備マスタの最大耐久
- `equipped: true` の装備は、種別ごとに 1 つまで・現在のジョブで装備できるもの

## 置き場所（案）

| 案 | 内容 | 良い点 | 注意点 |
| --- | --- | --- | --- |
| A | リポジトリに JSON を置く（例 `server/debug-templates/*.json`） | レビューされる、環境をまたいで同じものを使える | 追加・変更に PR が必要 |
| B | 画面から JSON を貼り付け／ファイル選択して取り込む | 手元で自由に作れる | 共有しにくい |
| C | スプレッドシートのタブ | マスタデータと同じ運用 | 入れ子の構造（装備・アイテムの一覧）を表にしにくい |

おすすめは **A＋B**。あわせて「今の自分のデータを JSON で書き出す」機能を作り、ステージングで作った状態を書き出して A に置く、という流れにする（テンプレートを手で書かずに済む）。

## 取り込みの挙動（案）

- 対象のデータは**上書き**（今あるスキル・装備・アイテム・ペットなどは消してテンプレートの内容にする）。画面で「現在のデータは失われます」と確認する
- 1 つのトランザクションで行い、プレイヤーの行をロックする（`DbPlayerMutationService` と同じく `FOR UPDATE`）。終わったらプレイヤーのキャッシュを消す
- 取り込む前に検証し、1 つでも不正なら何も書き換えない
  - マスタに存在する ID か（スキル・アイテム・装備・敵）
  - レベル 1〜100、ステータスは `Status` の制約どおり、スキルは 10 スロット・重複なし
  - 装備中の装備は種別ごとに 1 つまで・現在のジョブで装備可能
  - アイテムはスタック上限以下

## 実装の構成（案）

| 層 | 追加するもの |
| --- | --- |
| application/debug | `DebugTemplate`（上の JSON に対応する record）、`DebugTemplateValidator`、`DebugTemplateService`（一覧・書き出し・取り込み） |
| domain/player | `IDebugTemplateRepository`（テンプレートの一覧・取得）、`IPlayerDataOverwriter`（取り込みの書き込み） |
| infrastructure | `FileDebugTemplateRepository`（案 A）、`DbPlayerDataOverwriter`（トランザクションで各テーブルを置き換え） |
| endpoints | `GET /debug/templates`、`GET /debug/player/export`、`POST /debug/player/import`（`{ templateId }` または `{ template }`） |
| フロント | デバッグ画面に「テンプレート」セクション（一覧から選んで取り込み、JSON の貼り付け、書き出し） |

`domain/player` と `infrastructure` に追加があるので、実装の PR では先に ER 図（変更なしの確認）とドメイン図を更新する。

## PR の分け方（案）

1. 書き出し：`DebugTemplate` の形式と `GET /debug/player/export`、画面の「書き出し」ボタン（データを変更しないので先に出せる）
2. 取り込み：検証、`DbPlayerDataOverwriter`、`POST /debug/player/import`、画面の取り込み（JSON 貼り付け）
3. テンプレートの置き場所（案 A）と一覧、最初のテンプレート数個

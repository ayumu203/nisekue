# 装備機能仕様ドラフト

## 目的

`feat: 【クエスト·訓練】武器·防具の追加` を実装する前提として、現時点で未確定な仕様を整理する。

今回の Issue で確定したい要求は以下とする。

* 各武器・防具ごとに熟練度を持つ。
* 武器・防具ともに耐久値を持つ。
* 耐久値はクエストにて消費される。
* それぞれが各種パラメータに影響を与える。
* 装備中のアイテムによりステータスの表記が変化する。
* 装備の効果はダメージ計算時に加味される。

## 現状設計との接点

既存設計を読む限り、装備機能はまだ未導入であり、以下の前提で戦闘が組まれている。

* `CoreDomain.Player` は恒久ステータスとして `Status` と `MoveSet` を持つが、装備スロットや所持品は持たない。
* 特訓は `Player.Status` をそのまま `TrainingBattleFactory` へ渡している。
* クエストは開始時に `Player.Status` を `QuestRunPartyMemberSnapshot.BaseStatus` へ固定化している。
* `BattleDomain` は `BattleActorSnapshot.BaseStatus` を基準に有効ステータスを組み立てており、装備補正を差し込む専用概念はまだない。
* `docs/MKD02_クエスト設計.md` では現状「装備システムの詳細」はスコープ外としている。

このため、装備を入れるなら少なくとも以下のどれかを定義する必要がある。

* `Player` は素の `Status` を持ち、装備込みの戦闘用 `EffectiveStatus` を別で組み立てる。

## 先に決めるべき論点

### 1. 装備の永続化単位

最初に決めるべきなのは、「プレイヤーが何を所有しているか」をどの粒度で保存するかである。

未確定:

* 装備ごとに耐久値を持つ以上、プレイヤー所持装備の個体を分ける必要がある。 
* 同じ装備を複数個所持できる。
* 所持品と装備中を分ける。

### 2. 装備スロット構成

未確定:

* 初期スコープは `武器 1 + 防具 1` の 2 スロットでよい。
* ジョブごとの装備制限を入れる。

### 3. 熟練度の粒度

Issue 文の「各武器・防具ごとに熟練度を持つ」が曖昧である。

未確定:

* 熟練度は「装備マスタ単位」。
* 熟練度は「所持装備個体単位」。
* 熟練度は「訓練」にて上昇する（今回のIssueでは対応しない）

### 4. 耐久値の消費タイミング

Issue 文では「クエスト、訓練にて消費される」までは決まっているが、消費量の単位が未定である。

未確定:

* 訓練 1 回ごとに固定消費。
* クエスト 1 回ごとに固定消費。

### 5. 耐久値 0 の扱い

未確定:

* 耐久値 0 になった時点で自動解除し、削除。
* 修理は別Issue

### 6. どのパラメータへ影響するか

Issue 文では「各種パラメータに影響を与える」とあるが、対象ステータスが未定である。

* `MaxHp`, `MaxMp`, `Strength`, `Defense`, `Intelligence`, `Luck`, `Speed` の全てに補正可能。
* 乗算補正も持つ。

### 7. ステータス表示の仕様

* 装備名、熟練度、耐久値を同一パネルで見せる。
* クエスト中のステータス表示は途中の耐久変化を反映しない。
* ホーム画面は「最終値」を主表示にし、必要なら補助テキストで `(+N)` を出す。


### 8. ダメージ計算への反映方法

* 戦闘投入時に `装備補正込み Status` を生成する。
* クエストは開始時にその値を `QuestRunPartyMemberSnapshot.BaseStatus` へ固定する。
* 訓練は開始時にその値を `TrainingBattleFactory` へ渡す。

### 9. クエストのスナップショット境界

既存のクエストは開始時に `Status` / `MoveSet` / `ImagePath` を固定する方針である。
* クエスト中は装備状態を固定し、終了時にまとめて耐久値を減らす。
* クエスト中に装備変更を禁止する。

### 10. 特訓での扱い

* 特訓では耐久値を消費しない。
* 特訓で熟練度を1上げる。

### 11. 熟練度の効果

* 熟練度は命中やクリティカルのような別パラメータへ影響しない。
* 熟練度の上限は装備マスタにより決定、成長量はその基本ステータス値に対して効果値の1%。

### 12. API 追加範囲

* プレイヤー取得 API に装備情報を含めるか。
* 装備変更 API を今回入れるか。
* 修理 API、装備一覧 API、所持品 API は今回は入れない。
* `GET /player` 系レスポンスへの装備情報追加
* 装備変更 API
* クエスト/訓練処理での耐久消費反映


## 先に決めると実装が進めやすい最小仕様

設計を止めずに前へ進めるための最小仕様案は以下。

* 装備枠は `武器 1`、`防具 1` のみ。
* 各装備は「装備マスタ」と「プレイヤー装備個体」を分ける。
* 耐久値は個体単位で持つ。
* 熟練度は個体単位で持つ。
* 補正対象は既存 `Status` の 7 パラメータのみ。
* 補正方式は固定値加算のみ。
* クエストは開始時に装備補正込み `Status` をスナップショット化する。
* クエスト中に装備変更はしない。
* クエストの耐久消費は終了時にまとめて反映する。
* 訓練は開始時に装備補正込み `Status` を使い、終了後も耐久値は変化させない。
* 耐久値 0 の個体は削除せず `Broken` として保持する。
* 装備可能職業は CSV で定義する。
* 初期実装ではシード配布された装備に対して装備変更 API のみを提供する。

## 整理結果

* 「戦闘開始時に装備補正込み `Status` を作り、クエスト/特訓へ渡す」という方針は既存のスナップショット設計と整合する。
* クエスト中に装備変更しない方針は、`QuestRunPartyMemberSnapshot` に戦闘能力を閉じ込める既存方針と整合する。
* 訓練で開始時ステータスを固定し、終了時に耐久を反映する方針は、1 リクエスト完結の特訓仕様と整合する。
* 補正対象を既存 `Status` の 7 パラメータに限定する方針は、BattleDomain への影響を局所化しやすい。
* 装備マスタとプレイヤー装備個体を分ける方針は、耐久値を個体単位で持たせる前提と整合する。

以下の論点は確定したため、設計工程へ進める前提を満たしたものとする。

## 確定仕様

### A. 熟練度の保存単位と効果範囲

* 熟練度は装備個体ごとに保持し、他の同名装備とは共有しない。
* 武器・防具は 1 つの装備テーブルで管理し、種別を区別する列を持つ。
* 熟練度は今回は戦闘計算・装備制限・装備条件には使用しない。
* ただし将来利用に備えて、必要な保持カラムはあらかじめ用意する。

### B. 耐久値 0 の扱い

* 耐久値 0 の装備個体は削除しない。
* 所持品として残し、`Broken` 状態として扱う。
* `Broken` 状態の装備は装備不可とする。

### C. ジョブごとの装備制限

* 装備可能職業は CSV で定義する。
* 装備可否判定は装備マスタごとに持つ職業定義を参照する。

### D. 装備の入手・初期配布

* 初期実装ではシードデータによりプレイヤーへ初期装備を配布する。
* 将来的にはステージクリア報酬で装備を入手できるよう拡張する。

### E. 今回の API スコープ

* 今回は「所持装備 2 件を配布した状態で装備変更だけ可能」のスコープに限定する。
* 装備変更 API を実装し、装備切り替えと戦闘反映の動作確認を優先する。
* 装備ドロップ・購入・修理 API は別 Issue とする。

### F. 耐久消費量

* クエストの耐久消費は 1 回につき `1` とする。
* クエストの耐久消費は成否にかかわらず固定値で消費する。

## 現時点の設計着手方針

今回の確定仕様に基づき、設計工程では次を前提とする。

* 初期スコープは `武器 1 + 防具 1` の 2 スロットに限定する。
* 装備マスタは武器・防具共通テーブルで持ち、`EquipmentType` 列で種別を区別する。
* プレイヤー所持装備個体は、耐久値・熟練度・装備状態・破損状態を個体単位で保持する。
* 装備補正は `Status` の 7 パラメータに対する固定値加算のみとする。
* クエスト/特訓ともに戦闘開始後は装備変更を禁止し、開始時の装備補正込み `Status` を使う。
* ジョブ制限は装備マスタの CSV 定義を参照して装備変更時に検証する。
* 耐久値 0 の個体は `Broken` として保持し、装備不可かつ UI 上で区別表示できるようにする。
* 初期実装ではシード配布された装備を対象に、取得 API と装備変更 API のみを提供する。

## 今回確定した回答

1. 初期スコープの装備枠は `武器 1 + 防具 1` とする。
2. 耐久値と熟練度は「装備個体単位」で持つ。
3. 耐久値消費は「訓練 1 回固定」「クエスト 1 回固定」とする。
4. 耐久値 0 の装備は削除せず `Broken` として保持する。
5. 熟練度は今回は戦闘効果に使わず、保持と表示に留める。
6. 補正対象は既存 `Status` の 7 パラメータのみとする。
7. ステータス UI は「最終値 + 補助で補正値表示」を前提に設計する。

# エンドレス戦闘モード設計

レベル1相当から始まり、潜るほど（フロアが進むほど）敵が加速度的に強くなる、ソロ専用・終盤アンロック型の手続き的生成クエストステージ。「どこまで潜れるか（到達フロア）」を競うコンテンツ。

関連ドキュメント:
- ドメイン: [04_クエストドメイン.mmd](04_クエストドメイン.mmd)（`ProgressionType` / エンドレス生成経路）
- DB: [../db/01_ER図.mmd](../db/01_ER図.mmd)（`players.endless_best_floor`）
- 命名規則: チビクエ風のゆるい日本語（メモリ参照）

---

## 1. コンセプトと前提

- **手続き的生成**: フロアを事前定義せず、進入時にフロア番号 `n`（通算）から動的生成する。1 フロア = 1 戦闘。
- **ソロ専用**: パーティ人数は 1。ランキングを人数で交絡させない。
- **終盤アンロック型**: 既存 `MapUnlockFlag` 基盤を流用し、アイテム使用で開放（後述）。
- **既存の有限ステージ（Static）とは別モード**として共存させる。

---

## 2. 敵のスケーリング設計

### 2.1 倍率モデル

- 敵ステータス = **アーキタイプ基準ステータス `S_base` × 成長倍率 `f(n)`**（全ステータス一律倍率）。
- `S_base` はフロア1相当の基準値。アーキタイプ（後述）ごとに配分が異なる。

### 2.2 成長倍率 `f(n)`（多項式・超線形）

```
f(n) = 1 + a * n^p        （n = 通算フロア番号, 1 始まり, p > 1）
```

- `p > 1` により、1 フロアあたりの増分 `≈ a * p * n^(p-1)` がフロアが進むほど増える＝「奥ほど成長スピードが上がる」。
- 指数関数（等比）と異なり爆発が緩やかで、深層まで到達可能。
- **初期値: `p ≈ 2`。`a` と `p` はシミュレーションで決定**（第12章）。

### 2.3 安全上限フロア `cap`

- `S_base_max * f(cap)` が `int` 範囲（`int.MaxValue`）を超えない最大フロアを `cap` とする。**シミュレーションで逆算**。
- 多層防御として、敵ステータス生成時に各値を `int` 範囲（および HP 等の表示上限）にクランプする。
- `cap` 到達でランは強制終了（蓄積報酬は獲得）。

---

## 3. フロア構成

### 3.1 テーマ（深さ帯）

- 深さを **5 テーマ × 各 10 フロア = 50 フロア** に分割。
  - テーマ1: フロア 1–10 / テーマ2: 11–20 / … / テーマ5: 41–50。
- モチーフ: **自然の荒れ模様**（弱→強）。
  1. そよかぜ草原
  2. ざわめき森
  3. みぞれ峠
  4. ふぶき山
  5. あらしの果て（最終帯はダーク系を交える）
- **フロア50超はテーマを循環**（見た目はループ、ステータスは `f(n)` で上昇継続。例: 51–60 はテーマ1の見た目）。

### 3.2 敵プールとアーキタイプ

- 敵定義は **計 50 体**（テーマごと 10 体: 通常9体 + ボス1体）。
- **アーキタイプ 3 種**（既存 `EnemyAiType` に対応）:
  - 攻撃型（Aggressive）: strength / speed 高、defense 低
  - 防御型（Defensive）: max_hp / defense 高、speed 低
  - 支援型（Supportive）: intelligence / max_mp / luck 高
- 各テーマの内訳: **攻撃×3 / 防御×3 / 支援×3 / ボス×1**。
- 技（move）は**アーキタイプ固定・既存の `PowerRate` 型を流用**（深さでの差し替えなし。ダメージは攻撃ステ×PowerRate でステスケールに追随する。固定値 `FixedPower` 単独型は深層で無力化するため避ける）。
- 各アーキタイプの基準ステ配分はシミュレーションで決定（第12章）。

### 3.3 各フロアの編成

- 通常フロア: その帯の通常敵プールから **1〜3 体ランダム抽選**。
- **10 フロアごと（10, 20, 30, …）がボスフロア**: その帯のボス1体。
  - ボスは専用基準ステ + 追加倍率（例 ×1.5）+ 報酬ボーナス。
- 敵の見た目・名前はテーマ帯に紐づく。ステータスは `f(n)`（n は通算）で決まる。

---

## 4. 報酬

- **報酬は exp / gold のみ**。装備・アイテムのドロップなし。**ペット捕獲不可**。
- フロアクリアごとに `QuestRewardAccumulator` に exp / gold を加算（既存挙動）。
- **報酬カーブは緩やか（インフレ抑制）**:
  ```
  フロア報酬(exp) = Σ(敵の実効Level) * RewardRate
  ```
  - 敵の実効 Level は深さに対し**線形系**（敵ステの超線形より緩やか）。係数 `RewardRate` は敵倍率 `f(n)` とは独立のパラメータとし、シミュレーションで他ステージとの稼ぎ効率を見て決定。
- 全滅・撤退・cap 到達のいずれでも、それまでの蓄積 exp / gold は獲得（既存の Failed 時付与挙動）。

---

## 5. 終了・参加・アンロック

### 5.1 終了条件

1. パーティ全滅（Failed）
2. 任意リタイア（既存 `Escape` 流用、生存したまま撤退）
3. `cap` 到達（強制終了）

いずれも蓄積 exp / gold を獲得し、到達フロアをベスト記録に反映。

### 5.2 参加条件

- パーティ人数 1（ソロ専用）。
- `recommended_level` は表示用に控えめな値。
- クールダウンは既存共通。

### 5.3 アンロック

- 既存の `MapUnlockFlag` 機構を流用。
  - **`MapUnlockFlag.Map3 = 0x4`** を新設。
  - エンドレスステージの `required_map_unlock_flag = 4`。
- 開放アイテム: **`はがねの墓場`（stage 8）のドロップに新規 `UnlockMap` アイテムを追加**（`item_master.csv`、`item_id = 3077`、`map_unlock_flag = 4`、`max_stack = 1`）。使用でプレイヤーに `Map3` フラグ付与。
- アイテム名・墓場ドロップ率はシミュレーション/バランス時に決定。

## 9. ドメイン / アプリケーション変更点

- `QuestStageDefinition`: `ProgressionType` を保持。Endless では `Floors` を事前確定しない（または基準のみ）。
- **エンドレスフロア生成経路を新設**（例: `QuestEndlessFloorGenerator`）。
  - 入力: 通算フロア番号 `n`、エンドレス設定、テーマ別敵テンプレ。
  - 出力: そのフロアの敵 `QuestEnemyState[]`（`S_base × f(n)` をクランプ適用）と配置・ボスフラグ。
  - 既存 `QuestRun.StartNextFloor(nextEnemies, isBossFloor, nextPlacements, …)` が動的敵を受け取れるため、この経路に接続する。
- 完了判定: Static は `finalFloorNo` 到達で `MarkSucceeded`。**Endless は「完了」を持たず**、終了は全滅 / 撤退 / cap 到達のみ。
- ラン終了時に `endless_best_floor` を更新する処理を追加。
- 捕獲・ドロップ系はエンドレスでは無効化（exp/gold のみ）。

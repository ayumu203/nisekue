# 特訓機能

* プレイヤーが単独で特訓用の敵と戦い、経験値を獲得する機能とする。
* 特訓は一覧から選んだ 1 体の特訓敵に対して実行する。
* 実装方針として BattleDomain の `BattleService` を利用し、特訓のターン進行を共通戦闘基盤へ寄せる。
* 特訓結果は `Win` / `Lose` / `Draw` の 3 種類とする。
* 特訓終了後はプレイヤーへ経験値を付与し、必要に応じてレベルアップ判定を行う。

## 特訓敵について

* 特訓敵は `TrainingEnemy` として管理する。
* 特訓敵は `Id`、`Name`、`ImagePath`、`Level`、`Status` を持つ。
* 特訓敵は永続データとして `MoveSet` を持たず、特訓実行時に `TrainingBattleFactory` が暗黙の通常攻撃技を組み立てる。
* 敵名は 1 文字以上 20 文字以下とする。
* 画像パスは 1 文字以上 200 文字以下とする。
* レベルは 1 以上とする。
* 特訓敵一覧 API では `Id`、`Name`、`ImagePath`、`Level` のみ返す。
* 特訓敵一覧は `Level` 昇順、同レベル時は `Id` 昇順で返す。

## 特訓開始条件

* 特訓実行には認証済みユーザーであることを必須とする。
* 認証ユーザーの `sub` または `NameIdentifier` から `PlayerId` を取得できない場合は `401 Unauthorized` とする。
* 指定したプレイヤーが存在しない場合は `404 NotFound` とする。
* 指定した特訓敵が存在しない場合は `404 NotFound` とする。
* クライアントは特訓開始時に 3 ターン分の使用技を指定する。
* 各ターンの指定技はプレイヤーが習得済みの `MoveSet` に含まれる技であることを前提とする。
* 特訓にはクールダウンを設ける。
* クールダウン秒数は 5 秒とする。
* クールダウン中に特訓を実行した場合は `429 Too Many Requests` を返す。
* クールダウン中レスポンスには `message`、`retryAfterSeconds`、`cooldownUntil` を含める。

## 戦闘の進行

* 特訓はプレイヤー 1 人と特訓敵 1 体の 1 対 1 で行う。
* 戦闘開始時の HP は、プレイヤー・敵ともにそれぞれの `Status.MaxHp` を使用する。
* 戦闘開始時の MP は、プレイヤー・敵ともにそれぞれの `Status.MaxMp` を使用する。
* 戦闘は最大 3 ターン行う。
* 各ターン開始時にどちらかの HP が 0 以下なら、そのターンの追加行動は行わない。
* 行動順は `Speed` の大小で決める。
* プレイヤーと敵の `Speed` が同値の場合はプレイヤーが先攻する。
* 各ターンの行動は BattleDomain の `BattleService.ResolveTurn` に委譲する。
* プレイヤーはクライアントから送られた 3 ターン分の技指定に従って毎ターン 1 回行動する。
* 敵は毎ターン 1 回、暗黙の通常攻撃技を使用する。
* 実装上は `TrainingBattleFactory` が特訓専用の固定 `ActorId` を割り当て、BattleDomain の行動順決定と両立した形で同速時のプレイヤー先攻を保証する。
* プレイヤーがそのターンに指定した技を使用するための MP を満たさない場合、そのターンのプレイヤー行動は `Wait` として扱う。
* プレイヤーが戦闘不能になった後の未消化ターン指定は無視する。

## ダメージ計算

* 敵が使用する暗黙の通常攻撃技は `MoveCategory.Attack` の単体攻撃とする。
* 攻撃側は `Intelligence > Strength` の場合に魔法型、そうでなければ物理型として扱う。
* 敵の魔法型暗黙技は `DamageEffect.AttackStat = Intelligence` を使用する。
* 敵の物理型暗黙技は `DamageEffect.AttackStat = Strength` を使用する。
* プレイヤー指定技のダメージ・効果は `Move` 定義に従う。
* 魔法型攻撃は防御側の `Intelligence` を参照してダメージ計算する。
* 物理型攻撃は防御側の `Defense` を参照してダメージ計算する。
* 基本ダメージ式は BattleDomain の `BattleDamageCalculator` に従う。
* 敵の暗黙技は追加効果・状態異常・バフ・罠・範囲化を持たせない。
* 敵の暗黙技は特訓専用の一時的な `Move` として生成し、CSV の技定義には依存しない。
* 先攻の攻撃で後攻の HP が 0 になった場合、後攻はそのターン行動しない。

## 勝敗判定

* 全ターン終了後の残 HP により結果を判定する。
* プレイヤー HP が 1 以上かつ敵 HP が 0 以下の場合は `Win` とする。
* プレイヤー HP が 0 以下かつ敵 HP が 1 以上の場合は `Lose` とする。
* 上記以外は `Draw` とする。

## 経験値計算

* 経験値は特訓終了時に 1 回だけ計算する。
* 総与ダメージは `敵の MaxHp - 戦闘終了時の敵 HP` とする。
* 基礎経験値は `max(1, 総与ダメージ / 10)` とする。
* レベル差は `abs(プレイヤーレベル - 敵レベル)` とする。
* レベル差が 5 以下の場合のレベル補正は `0.5` とする。
* レベル差が 6 以上 10 以下の場合のレベル補正は `0.2` とする。
* レベル差が 11 以上の場合のレベル補正は `0.0` とする。
* 勝敗補正は `Win = 1.2`、`Draw = 1.0`、`Lose = 0.8` とする。
* 最終経験値は `floor(基礎経験値 * (レベル補正 + 勝敗補正))` とする。
* 最終経験値は最低 1 を保証する。

## レベルアップと保存

* 計算した経験値は `Player.GainExp(exp)` で加算する。
* その後 `Player.LevelUp(growthValueRepository)` を呼び、レベルアップ可否を判定する。
* 特訓結果の保存時にはプレイヤーを `playerRepository.SaveAsync(player)` で保存する。
* 特訓で永続化されるのはプレイヤーの経験値・レベル関連の更新である。
* 特訓中の現在 HP は恒久データとして保存しない。

## API

### 特訓敵一覧取得

* `GET /training/enemies`
* 認証必須とする。
* レスポンスは `TrainingEnemyView[]` とする。
* 各要素は `Id`、`Name`、`ImagePath`、`Level` を持つ。

### 特訓実行

* `POST /training/execute`
* 認証必須とする。
* リクエストボディは `ExecuteTrainingRequest` とし、`EnemyId` と 3 ターン分の使用技を受け取る。
* 使用技はターン順固定の配列、または `Turn1` `Turn2` `Turn3` に相当する 3 件固定の入力として扱う。
* 各ターン入力はプレイヤーが使用したい `MoveId` を持つ。
* 指定した `MoveId` が未習得である場合の扱いは今後定義する。少なくとも MP 不足時はエラーにせず `Wait` とする。
* 正常時レスポンスは `TrainingResultView` とする。
* レスポンスは `TrainingResult`、`Turn`、`CurrentPlayerHp`、`MaxPlayerHp`、`CurrentEnemyHp`、`MaxEnemyHp`、`Exp`、`IsLevelUp` を持つ。

## 現状実装に基づく制約

* 特訓は 1 回のリクエストで 3 ターン分のプレイヤー行動入力を受け付ける。
* 敵 AI 分岐は持たず、敵は暗黙の通常攻撃技のみを使用する。
* プレイヤーはリクエストで技選択を行うが、戦闘中の再入力や途中変更はできない。
* MP 不足時はエラー応答ではなく、そのターンのみ `Wait` として処理する。
* BattleDomain を利用するが、少なくとも敵側の特訓専用行動では状態異常・バフ・罠・隊列・範囲攻撃は使用しない。
* 最大 3 ターン固定のため、長期戦にはならない。
* 引き分けでも経験値を獲得できる。
* 敗北時でも経験値を獲得できる。
* 特訓処理は 1 回の API 呼び出しで完結し、戦闘途中状態の再開は行わない。

## BattleDomain 置換時の互換方針

* `TrainingService` は `BattleService` を直接利用する。
* プレイヤー側はクライアントから受け取った 3 ターン分の `MoveId` をターンごとの `UseMove` として解決する。
* そのターンのプレイヤー指定技を使用するだけの MP がない場合、`UseMove` ではなく `Wait` として解決する。
* 敵の通常攻撃は BattleDomain の `NormalAttack` をそのまま流用せず、`TrainingBattleFactory` で互換用の暗黙技を生成する。
* 理由は、BattleDomain の `NormalAttack` は `Strength` 固定であり、特訓仕様の「知力型なら `Intelligence` を使う」条件を満たせないためである。
* 特訓では毎ターン、プレイヤーは指定技、敵は暗黙技を `Move` として解決する。
* 行動順の同速判定については、BattleDomain 本体へ特訓専用の分岐を持ち込まず、特訓入力生成側で固定 `ActorId` を用いてプレイヤー先攻条件を満たす。
* これにより、BattleDomain へ寄せつつも特訓固有の敵通常攻撃仕様と MP 不足時待機仕様を保つ。

## 将来的な拡張余地

* 現時点では 1 回の特訓リクエストで 3 ターン分の行動を事前入力する。
* 将来的には、敵ごとの定義済み技や AI 分岐を導入し、敵が暗黙通常攻撃以外を使用できるよう拡張可能とする。
* その際も `TrainingBattleFactory` を拡張点として扱い、行動選択ルールと使用技の組み立てを `TrainingService` 本体から分離したまま保つ。

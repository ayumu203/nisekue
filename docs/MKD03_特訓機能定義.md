# 特訓機能

* プレイヤーが単独で特訓用の敵と戦い、経験値を獲得する機能とする。
* 特訓は一覧から選んだ 1 体の特訓敵に対して実行する。
* 実装方針として BattleDomain の `BattleService` を利用し、特訓のターン進行を共通戦闘基盤へ寄せる。
* 特訓結果は `Win` / `Lose` / `Draw` の 3 種類とする。
* 特訓終了後はプレイヤーへ経験値を付与し、必要に応じてレベルアップ判定を行う。

## 特訓敵について

* 特訓敵は `TrainingEnemy` として管理する。
* 特訓敵は `Id`、`Name`、`ImagePath`、`Level`、`Status` を持つ。
* 特訓敵は永続データとして `MoveSet` を持たず、特訓実行時に `TrainingBattleFactory` が暗黙の通常攻撃スキルを組み立てる。
* 敵名は 1 文字以上 20 文字以下とする。
* 画像パスは 1 文字以上 200 文字以下とする。
* レベルは 1 以上とする。
* 特訓敵一覧 API では `Id`、`Name`、`ImagePath`、`Level` のみ返す。
* 特訓敵一覧は `Level` 昇順、同レベル時は `Id` 昇順で返す。
* 特訓敵一覧はプレイヤーレベルに応じて公開範囲を制御する。
* 公開対象は「プレイヤーレベル以下の特訓敵」と「次に到達可能な 1 段階上の特訓敵」までとする。
* 特訓敵レベルが `1, 5, 10, 20, 50, 75, 100, 150, 200, 250, 300` のとき、プレイヤーレベル `10` の一覧には `1, 5, 10, 20` を表示する。
* プレイヤーレベルが最大特訓敵レベル以上の場合は、全特訓敵を表示する。

## 特訓開始条件

* 特訓実行には認証済みユーザーであることを必須とする。
* 認証ユーザーの `sub` または `NameIdentifier` から `PlayerId` を取得できない場合は `401 Unauthorized` とする。
* 指定したプレイヤーが存在しない場合は `404 NotFound` とする。
* 指定した特訓敵が存在しない場合は `404 NotFound` とする。
* 特訓開始前に装備中個体の装備可否と破損状態を検証する。
* `Broken` 状態の装備は装備中として扱わず、装備変更後に特訓を開始する必要がある。
* クライアントは特訓開始時に 3 ターン分の使用スキルを指定する。
* 各ターンの指定スキルはプレイヤーが習得済みの `MoveSet` に含まれるスキルであることを前提とする。
* 特訓にはクールダウンを設ける。
* クールダウン秒数は 3 秒とする。
* クールダウン中に特訓を実行した場合は `429 Too Many Requests` を返す。
* クールダウン中レスポンスには `message`、`retryAfterSeconds`、`cooldownUntil` を含める。

## 戦闘の進行

* 特訓はプレイヤー 1 人と特訓敵 1 体の 1 対 1 で行う。
* プレイヤーの戦闘ステータスは、開始時点で装備補正込み `Status` を生成して使用する。
* 戦闘開始時の HP は、プレイヤー・敵ともにそれぞれの `Status.MaxHp` を使用する。
* 戦闘開始時の MP は、プレイヤー・敵ともにそれぞれの `Status.MaxMp` を使用する。
* 戦闘は最大 3 ターン行う。
* 各ターン開始時にどちらかの HP が 0 以下なら、そのターンの追加行動は行わない。
* 行動順は `Speed` の大小で決める。
* プレイヤーと敵の `Speed` が同値の場合はプレイヤーが先攻する。
* 各ターンの行動は BattleDomain の `BattleService.ResolveTurn` に委譲する。
* プレイヤーはクライアントから送られた 3 ターン分のスキル指定に従って毎ターン 1 回行動する。
* 敵は毎ターン 1 回、暗黙の通常攻撃スキルを使用する。
* 実装上は `TrainingBattleFactory` が特訓専用の固定 `ActorId` を割り当て、BattleDomain の行動順決定と両立した形で同速時のプレイヤー先攻を保証する。
* プレイヤーがそのターンに指定したスキルを使用するための MP を満たさない場合、そのターンのプレイヤー行動は `Wait` として扱う。
* プレイヤーが戦闘不能になった後の未消化ターン指定は無視する。
* 特訓中の装備変更はできない。

## ダメージ計算

* 敵が使用する暗黙の通常攻撃スキルは `MoveCategory.Attack` の単体攻撃とする。
* 攻撃側は `Intelligence > Strength` の場合に魔法型、そうでなければ物理型として扱う。
* 敵の魔法型暗黙スキルは `DamageEffect.AttackStat = Intelligence` を使用する。
* 敵の物理型暗黙スキルは `DamageEffect.AttackStat = Strength` を使用する。
* プレイヤー指定スキルのダメージ・効果は `Move` 定義に従う。
* 魔法型攻撃は防御側の `Intelligence` を参照してダメージ計算する。
* 物理型攻撃は防御側の `Defense` を参照してダメージ計算する。
* 基本ダメージ式は BattleDomain の `BattleDamageCalculator` に従う。
* 敵の暗黙スキルは追加効果・状態異常・バフ・罠・範囲化を持たせない。
* 敵の暗黙スキルは特訓専用の一時的な `Move` として生成し、CSV のスキル定義には依存しない。
* 先攻の攻撃で後攻の HP が 0 になった場合、後攻はそのターン行動しない。
* 熟練度は今回はダメージ計算に使用しない。

## 勝敗判定

* 全ターン終了後の残 HP により結果を判定する。
* プレイヤー HP が 1 以上かつ敵 HP が 0 以下の場合は `Win` とする。
* プレイヤー HP が 0 以下かつ敵 HP が 1 以上の場合は `Lose` とする。
* 上記以外は `Draw` とする。

## 経験値計算

* 経験値は特訓終了時に 1 回だけ計算する。
* 基礎経験値は `敵レベル * 3` とする。
* 総与ダメージは、戦闘中にプレイヤーが敵へ与えた実ダメージの合計とする。
* 実回復量は、戦闘中にプレイヤーが回復した HP のうち最大 HP を超過しない実回復分の合計とする。
* 生存率は `戦闘終了時のプレイヤー HP / プレイヤー MaxHp` とする。
* 攻撃貢献度は `clamp(総与ダメージ / 敵MaxHp, 0.0, 1.0)` とする。
* 回復貢献度は `clamp(実回復量 / プレイヤーMaxHp, 0.0, 1.0)` とする。
* 生存貢献度は `clamp(戦闘終了時プレイヤーHP / プレイヤーMaxHp, 0.0, 1.0)` とする。
* 貢献度補正は `0.2 + 0.5 * 攻撃貢献度 + 0.15 * 回復貢献度 + 0.15 * 生存貢献度` とする。
* レベル差は `敵レベル - プレイヤーレベル` とする。
* レベル差が `-6` 以下の場合のレベル補正は `0.3` とする。
* レベル差が `-5` 以上 `-3` 以下の場合のレベル補正は `0.6` とする。
* レベル差が `-2` 以上 `2` 以下の場合のレベル補正は `1.0` とする。
* レベル差が `3` 以上 `5` 以下の場合のレベル補正は `1.3` とする。
* レベル差が `6` 以上の場合のレベル補正は `1.5` とする。
* 勝敗補正は `Win = 1.0`、`Draw = 0.85`、`Lose = 0.7` とする。
* 最終経験値は `floor(基礎経験値 * レベル補正 * 勝敗補正 * 貢献度補正)` とする。
* 最終経験値は最低 1 を保証する。

## レベルアップと保存

* 計算した経験値は `Player.GainExp(exp)` で加算する。
* その後 `Player.LevelUp(growthValueRepository)` を呼び、レベルアップ可否を判定する。
* 特訓結果の保存時にはプレイヤーを `playerRepository.SaveAsync(player)` で保存する。
* 特訓で永続化されるのはプレイヤーの経験値・レベル関連の更新と、装備中個体の耐久値更新である。
* 特訓終了時、装備中だった武器・防具の耐久値をそれぞれ `1` 減らす。
* 耐久値が `0` になった個体は削除せず `Broken` として保存する。
* 特訓中の現在 HP は恒久データとして保存しない。

## API

### 特訓敵一覧取得

* `GET /training/enemies`
* 認証必須とする。
* レスポンスは `TrainingEnemyView[]` とする。
* 各要素は `Id`、`Name`、`ImagePath`、`Level` を持つ。
* 一覧は認証ユーザーのプレイヤーレベルに応じた公開範囲のみ返す。

### 特訓実行

* `POST /training/execute`
* 認証必須とする。
* リクエストボディは `ExecuteTrainingRequest` とし、`EnemyId` と 3 ターン分の使用スキルを受け取る。
* 使用スキルはターン順固定の配列、または `Turn1` `Turn2` `Turn3` に相当する 3 件固定の入力として扱う。
* 各ターン入力はプレイヤーが使用したい `MoveId` を持つ。
* 指定した `MoveId` が未習得である場合の扱いは今後定義する。少なくとも MP 不足時はエラーにせず `Wait` とする。
* 正常時レスポンスは `TrainingResultView` とする。
* レスポンスは `TrainingResult`、`Turn`、`CurrentPlayerHp`、`MaxPlayerHp`、`CurrentEnemyHp`、`MaxEnemyHp`、`Exp`、`IsPlayerLevelUp`、`IsJobLevelUp`、`NewlyLearnedMoves` を持つ。
* 必要に応じて装備耐久変化後の装備情報を同レスポンスまたは後続のプレイヤー取得 API で確認できるようにする。

## 現状実装に基づく制約

* 特訓は 1 回のリクエストで 3 ターン分のプレイヤー行動入力を受け付ける。
* 敵 AI 分岐は持たず、敵は暗黙の通常攻撃スキルのみを使用する。
* プレイヤーはリクエストでスキル選択を行うが、戦闘中の再入力や途中変更はできない。
* MP 不足時はエラー応答ではなく、そのターンのみ `Wait` として処理する。
* 特訓経験値は火力職向けの与ダメージだけでなく、回復職向けの実回復量と盾職向けの戦闘終了時 HP も評価に含める。
* BattleDomain を利用するが、少なくとも敵側の特訓専用行動では状態異常・バフ・罠・隊列・範囲攻撃は使用しない。
* 最大 3 ターン固定のため、長期戦にはならない。
* 引き分けでも経験値を獲得できる。
* 敗北時でも経験値を獲得できる。
* 特訓処理は 1 回の API 呼び出しで完結し、戦闘途中状態の再開は行わない。

## BattleDomain 置換時の互換方針

* `TrainingService` は `BattleService` を直接利用する。
* プレイヤー側はクライアントから受け取った 3 ターン分の `MoveId` をターンごとの `UseMove` として解決する。
* そのターンのプレイヤー指定スキルを使用するだけの MP がない場合、`UseMove` ではなく `Wait` として解決する。
* 敵の通常攻撃は BattleDomain の `NormalAttack` をそのまま流用せず、`TrainingBattleFactory` で互換用の暗黙スキルを生成する。
* 理由は、BattleDomain の `NormalAttack` は `Strength` 固定であり、特訓仕様の「知力型なら `Intelligence` を使う」条件を満たせないためである。
* 特訓では毎ターン、プレイヤーは指定スキル、敵は暗黙スキルを `Move` として解決する。
* 経験値計算で使用する総与ダメージと実回復量は、BattleDomain の `BattleTurnResolution.ActionResults` からターンごとに集計する。
* 行動順の同速判定については、BattleDomain 本体へ特訓専用の分岐を持ち込まず、特訓入力生成側で固定 `ActorId` を用いてプレイヤー先攻条件を満たす。
* これにより、BattleDomain へ寄せつつも特訓固有の敵通常攻撃仕様と MP 不足時待機仕様を保つ。

## 将来的な拡張余地

* 現時点では 1 回の特訓リクエストで 3 ターン分の行動を事前入力する。
* 将来的には、敵ごとの定義済みスキルや AI 分岐を導入し、敵が暗黙通常攻撃以外を使用できるよう拡張可能とする。
* その際も `TrainingBattleFactory` を拡張点として扱い、行動選択ルールと使用スキルの組み立てを `TrainingService` 本体から分離したまま保つ。
